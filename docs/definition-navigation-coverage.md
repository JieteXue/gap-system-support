# Definition Navigation Coverage

This document records the statically recognizable GAP definitions supported by
the VS Code definition and reference providers. For editor behavior, Peek
rules, caching, and verification, see
[Definition And Reference Navigation](navigation.md).

## Lexical Definitions

- Global and local `:=` assignments
- Functions, atomic functions, and lambdas
- Ordinary, variadic, `readonly`, and `readwrite` parameters
- `local` declarations
- `for` loop variables
- Lexical shadowing and nearest preceding assignment

## Record And Component Definitions

- Fields declared inside `rec(...)`
- Dotted assignments such as `A.B.C := ...`
- Component assignments such as `A!.B := ...`
- Complete-path matching, so `A.Print` and `B.Print` remain distinct
- Calls through record and component selectors

## Global Aliases

- Identifier and qualified-record targets such as `ME := MagneticEquivalence`
  and `Compare := MagneticEquivalence.Compare`
- Chained global aliases and bindings imported by literal `Read()` calls
- Cursor-sensitive alias assignments: a later binding does not change an
  earlier occurrence
- Qualified uses whose root is renamed, without merging unrelated paths
- Reverse references from canonical definitions to uses through aliases

Alias normalization covers syntactically recognizable global assignments.
It is not general scope-sensitive alias analysis: local aliases, computed
selectors, conditional execution, and runtime rebinding are not fully modeled.
Circular alias chains terminate without executing GAP.

## Returned Record Fields

- Fields of `result := Function(...)` when the function returns `rec(...)`
- Multiple return paths, preserving each field's source location
- Forwarding functions and parameters passed through wrappers
- Fields used inside named function bodies, inferred from known workspace
  call arguments rather than requiring a result variable at the cursor
- Nested fields reached through local assignments and returned records
- List element origins from list literals, indexing, and `Add(list, value)`
- Element bindings inside `for element in list do ... od` bodies
- Hover and Go to Definition share the same field origins; references can
  connect the returned field to differently named result variables

This is bounded source tracing, not GAP execution or complete type inference.
List elements are treated as possible alternatives, not evaluated by index.
Conditional mutations, arbitrary list transformations, closures, dynamically
selected functions, and fields created only at runtime may remain unresolved.
Field availability on every return path is not guaranteed.
Parameter-field origins are possible input alternatives from recognizable
callers, not a declared parameter type. Callees are matched by definition
location, including global aliases, to avoid mixing same-named functions or
shadowed locals. Missing, unknown, and recursive-only arguments provide no
guaranteed origin. Higher-order calls and callers outside the workspace may
remain unresolved.

## GAP Declaration APIs

- Global functions, variables, names, and info classes
- Operations, attributes, properties, categories, filters, representations,
  constructors, and tag-based operations
- Synonyms and obsolete synonyms
- Kernel and supported declaration variants whose first argument is the
  declared GAP name

APIs such as `DeclareAutoreadableVariables` and `DeclareUserPreference` are not
treated as direct symbol declarations because their first argument is package
metadata or a configuration record.

## GAP Installation And Binding APIs

- `InstallGlobalFunction`
- `InstallMethod`, `InstallOtherMethod`, and supported method variants
- `InstallEarlyMethod`, `InstallImmediateMethod`, `InstallTrueMethod`, and
  `InstallTagBasedMethod`
- `InstallValue`
- `BindGlobal`, `BindConstant`, `BindThreadLocal`, and
  `BindThreadLocalConstructor`

## Cross-File Resolution

- Literal `Read("path")` chains
- Nested and circular `Read()` chains
- Open unsaved documents participating in a `Read()` chain
- Workspace fallback across `.g`, `.gd`, `.gi`, and `.gap` files

The workspace fallback covers computed loading expressions such as
`Read(Concatenation(...))`, where the target path cannot be recovered from a
single string literal.

## Static Limits

GAP can create names dynamically at runtime. Static navigation cannot
guarantee a target for:

- Computed global names
- Dynamic record selectors such as `record.(expression)`
- Definitions generated by arbitrary function calls or `EvalString`
- Symbols supplied only by an installed GAP package with no source in the
  current workspace

For these cases, runtime introspection would require a separate GAP process and
is outside the current VS Code-only definition provider.
