# Definition Navigation Coverage

This document records the statically recognizable GAP definitions supported by
the VS Code definition and reference providers. For editor behavior, Peek
rules, caching, and verification, see
[Definition And Reference Navigation](navigation.md).

## Lexical Definitions

- Global and local `:=` assignments
- Functions, atomic functions, and lambdas
- Ordinary, variadic, `readonly`, and `readwrite` parameters
- `local` declarations
- `for` loop variables
- Lexical shadowing and nearest preceding assignment

## Record And Component Definitions

- Fields declared inside `rec(...)`
- Dotted assignments such as `A.B.C := ...`
- Component assignments such as `A!.B := ...`
- Complete-path matching, so `A.Print` and `B.Print` remain distinct
- Calls through record and component selectors

## GAP Declaration APIs

- Global functions, variables, names, and info classes
- Operations, attributes, properties, categories, filters, representations,
  constructors, and tag-based operations
- Synonyms and obsolete synonyms
- Kernel and supported declaration variants whose first argument is the
  declared GAP name

APIs such as `DeclareAutoreadableVariables` and `DeclareUserPreference` are not
treated as direct symbol declarations because their first argument is package
metadata or a configuration record.

## GAP Installation And Binding APIs

- `InstallGlobalFunction`
- `InstallMethod`, `InstallOtherMethod`, and supported method variants
- `InstallEarlyMethod`, `InstallImmediateMethod`, `InstallTrueMethod`, and
  `InstallTagBasedMethod`
- `InstallValue`
- `BindGlobal`, `BindConstant`, `BindThreadLocal`, and
  `BindThreadLocalConstructor`

## Cross-File Resolution

- Literal `Read("path")` chains
- Nested and circular `Read()` chains
- Open unsaved documents participating in a `Read()` chain
- Workspace fallback across `.g`, `.gd`, `.gi`, and `.gap` files

The workspace fallback covers computed loading expressions such as
`Read(Concatenation(...))`, where the target path cannot be recovered from a
single string literal.

## Static Limits

GAP can create names dynamically at runtime. Static navigation cannot
guarantee a target for:

- Computed global names
- Dynamic record selectors such as `record.(expression)`
- Definitions generated by arbitrary function calls or `EvalString`
- Symbols supplied only by an installed GAP package with no source in the
  current workspace

For these cases, runtime introspection would require a separate GAP process and
is outside the current VS Code-only definition provider.
